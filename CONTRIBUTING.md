# Contributing

Thanks for helping build Awesome SOC!

## Criteria for Inclusion

- **Real and actively maintained** — The tool or resource must be a real, publicly available project with recent activity. No abandoned software, no vaporware.
- **Useful for SOC work** — It must address a concrete SOC use case: triage, detection, investigation, threat intelligence, threat hunting, automation, IR, forensics, or training.
- **One-line description** — Descriptions must be practical and describe what the tool is used for in a SOC context. No marketing copy or vague hype.
- **Alphabetical order** — Entries must be sorted alphabetically within each section.
- **Verified URL** — Link to the official website or main GitHub repository. No tracking links, no referral links.

## How to Contribute

1. Fork the repository
2. Create a feature branch
3. Add your entry in alphabetical order within the appropriate category
4. Ensure the description is a single line using an em dash (` — `) separator
5. Submit a pull request

## Pull Request Checklist

- [ ] One-line practical description added in `Name — Description` format
- [ ] URL verified as the canonical source (official project site or main GitHub repo)
- [ ] Entry placed in alphabetical order within the correct category
- [ ] No duplicate entries exist
- [ ] Tool is actively maintained (commits or releases within the last 12 months)
- [ ] Description is practical and SOC-relevant (no marketing fluff)

## Proposing a New Category

New categories should represent a distinct, well-established domain within SOC operations. Open an issue to discuss before sending a PR for a new category.
